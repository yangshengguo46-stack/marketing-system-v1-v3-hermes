# 数据飞轮策略：营销系统数据复用与内容生产闭环

> 建立日期：2026-07-02
> 当前任务入口：[`../current/EXECUTION_LEDGER.md`](../current/EXECUTION_LEDGER.md)；高级视频历史方案：[`../deferred/high-end-video-volcengine.md`](../deferred/high-end-video-volcengine.md)。旧编号台账只可通过 Git 历史追溯。
> 核心问题：系统推向市场后产生大量数据，如何复用于内容生产，让系统越用越强。
>
> **上位概念：网感。** 所有数据飞轮、多 Agent 协同、爆款归因，最终都指向"网感"二字。
> 网感不是玄学，它是可分解、可学习、可复用的。小云雀的网感是平台喂的（通用模型），
> 火山剧创的网感是工业流程保证的（多 Agent 校验），而我们的网感是用户自己的真实数据喂出来的——
> 越用越准，这是 SaaS 产品对通用工具的降维打击。

## 一、系统会产生哪些数据

### 第一层：内容生产数据（直接复用于视频生成）

| 数据 | 来源 | 价值 | 复用方式 |
|---|---|---|---|
| **Prompt 效果库** | 每次文生图/视频的 prompt + 生成结果 + 用户是否采纳 | 极高 | 建立 prompt→效果映射，子 Agent 调用时自动检索相似场景的最佳 prompt |
| **风格一致性参数** | seed 值 + 描述词模板 + 跨镜头一致性评分 | 极高 | 固化为"风格预设"，新项目一键复用 |
| **镜头策略库** | 运镜描述 + 视频效果 + 完播率 | 高 | 对标火山剧创的"200+爆款镜头策略"，用真实数据驱动 |
| **资产复用库** | 角色/场景/道具图 + 被哪些项目复用 + 效果 | 高 | 跨项目跨账号复用，降低生成成本 |
| **FFmpeg 合成模板** | 剪辑参数 + 字幕样式 + 转场 + 贴纸 + 成片效果 | 高 | 固化为合成模板，用户一键套用 |

### 第二层：内容发布数据（反馈闭环）

| 数据 | 来源 | 价值 | 复用方式 |
|---|---|---|---|
| **发布表现数据** | 播放量/完播率/点赞/评论/转发/收藏 | 极高 | 回写到 content_assets，Agent 生产新内容时参考"同类内容历史表现" |
| **最佳发布时间** | 发布时间 + 初始播放曲线 | 高 | 排期队列自动优化发布时间 |
| **平台差异数据** | 同一内容在不同平台的表现差异 | 高 | 分发策略 Agent 自动调整各平台内容变体 |
| **评论/弹幕语义** | 用户评论的情感分析、关键词提取 | 高 | 反馈到内容选题和脚本优化 |
| **爆款归因** | 高播放量内容的共性特征（节奏/钩子/话题/风格） | 极高 | 归纳为"爆款因子"，注入剧本 Agent 和分镜 Agent |

### 第三层：账号运营数据（账号 DNA）

| 数据 | 来源 | 价值 | 复用方式 |
|---|---|---|---|
| **账号画像** | 账号内容历史 + 粉丝画像 + 平台标签 | 高 | 内容生产时自动对齐账号调性 |
| **账号成长曲线** | 粉丝增长 + 内容频率 + 表现趋势 | 中 | 运营建议 Agent 参考成长阶段给策略 |
| **违规/限流记录** | 发布失败 + 平台惩罚记录 | 高 | 内容审核 Agent 自动规避高风险内容 |

### 第四层：行业/市场数据（宏观复用）

| 数据 | 来源 | 价值 | 复用方式 |
|---|---|---|---|
| **公共热点** | DATA 模块采集 | 高 | 选题 Agent 自动追热点 |
| **跨账号趋势对比** | 多账号同行业表现对比 | 中 | 策略 Agent 发现行业机会 |
| **竞品内容样本** | 竞品账号内容采集 | 中 | 选题和风格参考 |

## 二、数据飞轮闭环

```
                    ┌─────────────────────────────────┐
                    │         数据飞轮闭环              │
                    └─────────────────────────────────┘
                                    │
    ┌───────────┐    ┌───────────┐  │  ┌───────────┐    ┌───────────┐
    │  选题 Agent │←──│ 爆款归因库 │  │  │ 发布表现  │──→│ 指标回收  │
    │  参考热点  │    │ 爆款因子  │  │  │ 回写      │    │ 评论语义  │
    └─────┬─────┘    └───────────┘  │  └───────────┘    └───────────┘
          │                         │         ↑
          ↓                         │         │
    ┌───────────┐              ┌───────────┐  │
    │ 剧本 Agent │←─────────────│ 记忆系统  │──┘
    │ 参考爆款结构│              │ MEM 模块  │
    └─────┬─────┘              └───────────┘
          │                         ↑
          ↓                         │
    ┌───────────┐    ┌───────────┐  │
    │ 文生图 Agent│←──│ Prompt 效果库│──┘
    │ 检索最佳prompt│   │ 风格预设  │
    └─────┬─────┘    └───────────┘
          │
          ↓
    ┌───────────┐    ┌───────────┐
    │ 视频生成   │←──│ 镜头策略库 │
    │ Agent     │   │ 资产复用库 │
    └─────┬─────┘    └───────────┘
          │
          ↓
    ┌───────────┐    ┌───────────┐
    │ 合成 Agent │←──│ 合成模板库 │
    └─────┬─────┘    └───────────┘
          │
          ↓
    ┌───────────┐
    │ 发布 → 指标回收 → 回写记忆 → 下一次生产更聪明 │
    └───────────┘
```

**核心逻辑**：每次内容生产不是"从零开始"，而是"检索历史最佳实践 → 生成 → 发布 → 回收指标 → 更新最佳实践"。系统用得越多，prompt 效果库越丰富，镜头策略越精准，风格预设越成熟。

| 模块 | 现状 | 可直接承载的数据 |

| 数据结构 | 用途 | 优先级 | 关联模块 |

## 四、数据隐私和合规边界

| 边界 | 规则 |
|---|---|
| **用户数据隔离** | 多用户场景下，A 用户的爆款因子不能直接给 B 用户用（除非脱敏聚合） |
| **平台数据合规** | 采集的评论/弹幕不能存储原文，只存语义分析结果 |
| **API Key 隔离** | 每个用户的火山引擎 API Key 独立，调用成本独立核算 |
| **资产版权** | AI 生成的图片/视频的版权归属和商用授权需记录 |
| **数据保留与删除** | 用户可导出和删除自己的全部数据；记忆衰减机制已有（MEM 模块） |

## 五、推进顺序

| 阶段 | 内容 | 前置条件 |
|---|---|---|
| **阶段 1** | prompt 效果库——VIDEO-02 adapter 里加记录逻辑，每次调用 API 记录 prompt + 结果 + 用户是否采纳 | VIDEO-02 实现 |
| **阶段 2** | 发布指标回收——拿到真实播放数据后回写到 content_assets 和记忆系统 | PUB 模块发布闭环 |
| **阶段 3** | 记忆系统对接——把 prompt 效果和发布指标写入记忆，Agent 生产时自动检索 | MEM-12~15 |
| **阶段 4** | 爆款因子归纳——用模型分析高表现内容的共性，归纳为可复用的策略 | 数据积累到一定量 |
| **阶段 5** | 跨用户脱敏聚合——行业级最佳实践（可选，需用户授权） | 规模化后 |

## 六、与视频生成板块的交叉引用

| 视频生成环节 | 可复用数据 | 飞轮效果 |
|---|---|---|
| 文生图 Agent | prompt 效果库 + 风格预设 | 检索同场景最佳 prompt，减少重试次数 |
| 图生视频 Agent | 镜头策略库 + 资产复用库 | 运镜描述自动推荐，资产跨项目复用 |
| 文生视频 Agent | prompt 效果库 | 同上 |
| 参考图/视频生视频 Agent | 风格预设 + 资产复用库 | 风格一致性自动保持 |
| 合成 Agent | 合成模板库 | 用户/行业最佳合成模板一键套用 |
| 导演编排 | 爆款因子 + 发布表现数据 | 编排策略参考历史表现最优的环节组合 |

## 七、待讨论问题（供审核）

1. **prompt 效果库的评分机制**：用户采纳/拒绝是最直接的信号，但如何量化"部分采纳"（用户修改了 prompt 后采纳）？
2. **爆款因子的归因方法**：高播放量内容的"爆款"归因——是选题、脚本结构、视觉风格、发布时间、还是平台算法？需要设计归因模型。
3. **跨用户数据聚合的隐私边界**：脱敏聚合到什么程度？是否需要用户明确授权？
4. **数据冷启动**：系统刚推向市场时没有历史数据，Agent 如何在不依赖历史数据的情况下保证质量？
5. **数据衰减策略**：平台算法会变化，旧的爆款因子可能失效。如何设计时效性权重？
6. **成本与收益的平衡**：prompt 效果库越大，检索成本越高。是否需要向量索引？用什么 embedding 模型？
