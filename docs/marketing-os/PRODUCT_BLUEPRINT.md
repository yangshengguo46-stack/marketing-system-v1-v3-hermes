# 智能营销产品蓝图

## 产品承诺

用户只需要完成三件事：连接账号、设置关注行业、确认关键决策。系统持续完成数据采集、账号监控、机会判断、选题生成、内容生产、发布和复盘，并能解释每个结论来自什么数据、哪些步骤失败、何时需要用户介入。

## 用户主流程

1. 在账号中心登录内容平台，并扫码连接微信或飞书随身助手；内容平台登录凭据只保留在 Electron 会话。
2. 设置关注行业、账号同步开关和每日巡检时间。
3. 系统复用登录态，无感同步账号指标并采集行业内容。
4. 后端去重、分类、匹配画像，产出有来源的趋势和选题。
5. 用户只审核方向；后续进入内容制作与发布。
6. 发布后回收真实指标，驱动下一轮选题和策略调整。
7. 巡检简报与异常自动推送到用户指定的微信/飞书会话，用户可直接追问方案和数据依据。

## 真智能闭环

```text
目标设置
  → 感知：账号指标、行业内容、公共热点
  → 判断：趋势去重、画像匹配、机会排序
  → 行动：生成选题、创建发布任务、执行已授权自动化
  → 观察：同步播放、互动、粉丝变化
  → 学习：调整行业权重、内容角度和发布时间
```

## 真实性契约

- 不使用演示数字冒充真实数据。
- 所有趋势和建议保留数据源、采集时间和查询目标。
- 单个步骤失败不伪装成整条任务成功；报告使用 `completed / partial / failed`。
- 登录态采集失败时可以降级公共热点，但必须明确标记来源。
- Cookie 不进入渲染进程和 Python 后端，不以明文落盘。
- 自动发布等外部副作用必须经过用户授权，失败要可追踪、可重试。
- AI 数据不足时必须说明，而不是编造结论。

## 当前架构

- Electron 主进程：平台登录态、隐藏页面采集、统一智能巡检编排和定时触发。
- React 前端：目标设置、实时进度、证据报告、人工审核和异常处理。
- FastAPI 后端：持久化、趋势分析、画像匹配、选题、账号/发布/分析数据接口。
- Hermes：微信/飞书消息网关与只读营销顾问；可读取最新营销上下文，发布等外部副作用仍需显式授权。

## 当前已完成

- Electron 登录态与无头采集共用同一会话。
- 行业目标持久化与多行业批量采集。
- 账号同步、行业采集、趋势分析、选题生成的统一巡检链路。
- 手动运行和每日定时运行使用同一套编排。
- 实时步骤进度、证据、错误与降级来源报告。
- 发布任务、真实分析汇总和 Hermes 只读咨询。
- macOS 独立后端打包与离线 Electron 构建。
- 微信与飞书扫码连接、可信用户绑定、首次私聊自动设置通知窗口、巡检推送和跨端连续对话。

## 后续优先级

### P0：形成可真实试用的闭环

- 代理/网络诊断与一键自检。
- 抖音登录身份识别、验证码可见回退和 DOM 适配监控。
- 账号内容列表与单条作品指标同步。
- 消息渠道重连、送达状态和通知失败重试。

### P1：从建议走向执行

- 选题审核、脚本版本、素材和发布任务之间的状态机。
- 平台发布前预览、显式授权、失败重试和审计记录。
- 发布指标自动回收，建立选题到结果的归因关系。

### P2：形成学习能力

- 根据账号历史表现动态调整行业与选题权重。
- 记录用户采纳/拒绝原因，优化推荐。
- 多账号差异化策略，而不是所有账号共用一套建议。
- 视频制作模块接入后纳入同一证据和审批链路。
