# Marketing OS 四类知识库与经营图谱架构

> 日期：2026-07-12
> 状态：当前知识边界基线
> 执行禁令：默认修改原生 owner；Electron 只负责显示和交互。

## 最小产品循环

```text
精准海量数据采集
→ 平台知识库 / 赛道与市场知识库 / 账号知识库 / 内容知识库
→ Preflight 预演
→ Action / Publish
→ Receipt / Metrics
→ Retro / Candidate / System Governance
→ 账号知识更新 + 匿名产品知识飞轮
```

这条闭环是后台基础设施，不是用户可配置功能。用户与对话只能读取当前有效知识及来源，不能读取内部候选队列，也不能创建、接受、拒绝、改写或恢复候选；系统按固定的来源、重复样本、时效、冲突、历史回放与伤害门禁静默晋级、降级、替换或淘汰。

系统写入由 [`agent/epistemic_contract.py`](../../../agent/epistemic_contract.py) 的进程内 capability 门禁：没有 `SystemAuthority`，repository 不能决定候选或投影知识。Gateway、Tool 和 Desktop 都没有序列化或构造该 capability 的入口。

## Human Observation Core 是上游研究系统

四库不再拥有“人类模型”。独立 `agent/human_observer/` 保存带权利合同的不可变原始观察、时间图谱、版本理论、竞争解释、封存预测、结果和模型修订；Marketing Receipt 只经后台单向 connector 贡献观察，四库和 Preflight 只能读取投影，不能回写或决定模型版本。

群体机制只允许 `identity_convergence / emotional_contagion / normative_pressure / suggestibility / deindividuation / polarization / imitation / authority_transfer / rumor_cascade / collective_effervescence / unknown`。`乌合之众` 是历史解释镜片，不是系统真理；它必须与社会认同、去个体化、规范涌现和信息级联等解释竞争，并保留反证、置信上限与数据缺口。

该内核由 Cron 和 system-only owner 静默驱动。用户和对话不能创建、修改、接受、拒绝或恢复其学习结论；单样本不能升级成人性规律，个人身份、逐条评论、永久人格类型和临床诊断永远不能进入。完整边界见 [`../../human-observer/ARCHITECTURE.md`](../../human-observer/ARCHITECTURE.md)。

## 四类知识不能混

### 平台知识库：术

回答“在这个平台应该怎样表达和分发”。包括平台规范、推荐机制的公开可观察抽象、格式、编辑器、内容治理、版权、负反馈、发布时间和平台表达差异。

- 必须有平台、地区、版本、生效时间、失效时间、来源和置信度。
- 官方规则与运营经验分开标记；经验不能冒充官方规则。
- 来源只能是内置审校版本、真实 EvidenceRecord 或签名聚合知识包。
- 用户和模型不能直接写入。

### 赛道与市场知识库：环境

回答“这个品类里谁在解决什么问题、需求和竞争怎样变化、哪些商业路径正在被验证”。包括品类结构、细分需求、受众迁移、供给密度、竞争空白、商业路径、季节与事件窗口。

- 必须带品类、地区、平台、时间窗口、来源、样本口径和置信度。
- 用户提出的“这个赛道肯定能赚钱”和模型生成的市场规模不能进入。
- 真实 EvidenceRecord 与满足隐私门槛的签名聚合知识包可以形成市场候选。
- 赛道路线是当前账号的经营假设；即使引用市场知识，也不能反向把假设写成公共市场事实。

### 账号知识库：这个账号的现实

回答“这个账号过去发生了什么、哪些模式被多次验证”。包括账号受众、内容表现模式、失败恢复、平台内适配、发布节奏和策略候选。

- 只属于一个 user/account scope。
- 只有发布/指标 Receipt 支持、经过 Retro 且通过系统门禁的 LearningCandidate 才能进入 active knowledge。
- 一次爆款、一次失败和用户自己的主观归因都不能直接成为账号知识。
- 用户目标、审美、拒绝和表达习惯属于用户记忆；它们能约束 Agent，但不能污染账号绩效事实。

### 内容知识库：道

回答“人为什么停下、看完、相信、转发和行动”。包括个体注意力、认知负荷、情绪唤醒、信任证据、身份表达、群体传播、社交风险和叙事结构。

- 心理学、社会学和营销模型只作为可检验先验，不是确定性读心术。
- 每条原理必须落到可观察变量，接受真实数据反驳和分群修正。
- 公共研究与匿名聚合规律进入这里；账号自己的结果优先进入账号知识库。
- 用户和模型不能直接把观点写成普遍人性规律。

## 对标经营图谱不是第五个知识库

对标图谱保存当前账号和外部账号的关系：直接竞争、议题、形式、信任、商业、跨赛道和反例。每个关系必须有匹配向量、选择理由、观察维度、EvidenceRecord 和观察时间。

它不声称“某账号的做法普遍有效”，也不把粉丝数当成相似性。只有经跨账号、跨时间聚合并通过治理的规律，才可能成为赛道或内容知识候选。

## 用户记忆不是第五个知识真相库

用户记忆保存用户明确偏好、拒绝、目标、表达习惯和协作方式。用户本人拥有确认、修改和撤回权，因为这里保存的真相是“用户这样陈述/选择”，不是“外部世界必然如此”。即使用户认知错误，Agent 也应理解“用户这样认为”，但不能把它升级成平台规则、账号绩效结论或普遍内容规律。

```text
用户说“抖音必须每天发十条”
→ 可记录为用户观点/偏好
→ 不进入平台知识库
→ 不进入账号知识库
→ 只有真实发布实验和回执支持后，才可能形成该账号的节奏候选
```

## 权威顺序

同一任务发生冲突时：

1. 当前账号本地真实 Receipt 与已接受账号知识。
2. 当前有效、可溯源的平台知识。
3. 当前有效、可溯源的赛道与市场知识。
4. 内容知识中的可检验原理。
5. 签名聚合先验。
6. 用户偏好只约束协作与表达，不改写事实。
7. 模型自身推断永远只是候选。

## 完成边界

当前已经完成结构化四库、内置基线、防用户/模型污染写入门、Receipt-backed 账号晋升、签名聚合知识投影和 Preflight 检索。Hermes Cron 现会静默执行已观察指标恢复、平台/市场知识时效与显式冲突隔离、三条以上公域作品且每条至少两次快照的市场聚合、真实发布复盘投影，以及权重候选的支持度/反例率/历史伤害回放；学习候选 list/decide RPC 与 Desktop 请求均已删除，repository 决策需要 system capability。赛道库仍需更大规模真实样本，平台官方规则的持续刷新仍依赖可信原生采集源或签名知识包，而不是对话输入。

Preflight 中的 `knowledge_support` 只表示 Marketing 四库覆盖与置信度，不直接证明内容质量。`content-production-preflight-v0.9` 已移除 Human Observation 覆盖因子和缺失警告；显式核心投影只可作为 `read_only_no_score_or_writeback` 上下文。缺个人历史时公开平台/市场/内容先验可支持低置信可逆草稿，但不能冒充账号个性化或精确流量预测；真实内容、证据、账号适配和发布回执仍决定产品结论。
