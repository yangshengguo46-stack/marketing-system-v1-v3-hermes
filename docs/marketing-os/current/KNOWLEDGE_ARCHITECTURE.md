# Marketing OS 三类知识库架构

> 日期：2026-07-12
> 状态：当前知识边界基线
> 执行禁令：默认修改原生 owner；Electron 只负责显示和交互。

## 最小产品循环

```text
精准海量数据采集
→ 平台知识库 / 账号知识库 / 内容知识库
→ Preflight 预演
→ Action / Publish
→ Receipt / Metrics
→ Retro / Candidate / Governance
→ 账号知识更新 + 匿名产品知识飞轮
```

## 三类知识不能混

### 平台知识库：术

回答“在这个平台应该怎样表达和分发”。包括平台规范、推荐机制的公开可观察抽象、格式、编辑器、内容治理、版权、负反馈、发布时间和平台表达差异。

- 必须有平台、地区、版本、生效时间、失效时间、来源和置信度。
- 官方规则与运营经验分开标记；经验不能冒充官方规则。
- 来源只能是内置审校版本、真实 EvidenceRecord 或签名聚合知识包。
- 用户和模型不能直接写入。

### 账号知识库：这个账号的现实

回答“这个账号过去发生了什么、哪些模式被多次验证”。包括账号受众、内容表现模式、失败恢复、平台内适配、发布节奏和策略候选。

- 只属于一个 user/account scope。
- 只有发布/指标 Receipt 支持、经过 Retro 且已 accepted 的 LearningCandidate 才能进入 active knowledge。
- 一次爆款、一次失败和用户自己的主观归因都不能直接成为账号知识。
- 用户目标、审美、拒绝和表达习惯属于用户记忆；它们能约束 Agent，但不能污染账号绩效事实。

### 内容知识库：道

回答“人为什么停下、看完、相信、转发和行动”。包括个体注意力、认知负荷、情绪唤醒、信任证据、身份表达、群体传播、社交风险和叙事结构。

- 心理学、社会学和营销模型只作为可检验先验，不是确定性读心术。
- 每条原理必须落到可观察变量，接受真实数据反驳和分群修正。
- 公共研究与匿名聚合规律进入这里；账号自己的结果优先进入账号知识库。
- 用户和模型不能直接把观点写成普遍人性规律。

## 用户记忆不是第四个知识真相库

用户记忆保存用户明确偏好、拒绝、目标、表达习惯和协作方式。即使用户认知错误，Agent 也应理解“用户这样认为”，但不能把它升级成平台规则、账号绩效结论或普遍内容规律。

```text
用户说“抖音必须每天发十条”
→ 可记录为用户观点/偏好
→ 不进入平台知识库
→ 不进入账号知识库
→ 只有真实发布实验和回执支持后，才可能形成该账号的节奏候选
```

## 权威顺序

同一任务发生冲突时：

1. 当前账号本地真实 Receipt 与已接受账号知识。
2. 当前有效、可溯源的平台知识。
3. 内容知识中的可检验原理。
4. 签名聚合先验。
5. 用户偏好只约束协作与表达，不改写事实。
6. 模型自身推断永远只是候选。

## 完成边界

当前已经完成结构化三库、内置基线、防用户/模型污染写入门、Receipt-backed 账号晋升、签名聚合知识投影和 Preflight 检索。尚未完成的是海量真实采集、平台规则自动时效巡检、完整指标回收、Retro 自动投影与 UI 治理。

Preflight 中的 `knowledge_support` 只表示知识覆盖与置信度，不直接证明内容质量。通用原理存在不能给烂内容加分；知识不足只会降低判断置信，真实内容、证据、账号适配和发布回执仍决定结论。
