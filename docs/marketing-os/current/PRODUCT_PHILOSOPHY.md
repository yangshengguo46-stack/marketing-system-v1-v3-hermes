# Marketing OS 产品哲学

## 最高优先级：先改原生 owner，禁止外围适配层惯性

默认先修改真正拥有能力的原生 owner。禁止因为怕碰上游、方便同步或短期省事，就在外围
增加适配层、桥接层、外挂 Provider、重复 MCP 或壳。只有源码证明确实没有合适 owner，且
新增边界具备明确长期价值时，才允许增加新层。

- Hermes 是产品源码本体，不是藏在 Marketing OS 外壳后的外部依赖。
- Hermes 或上游 MCP 已有更优能力时，直接修改和增强它，不在外面重做一份。
- 上游同步靠有意识的 merge、测试和冲突治理，不靠冻结核心源码。
- Skill 拥有领域操作知识，MCP 拥有外部执行，UI 只呈现意图和状态。
- 每次新增模块前必须回答：为什么不能进入现有原生 owner？没有源码证据，不得新建边界。
- “进入 Hermes”指进入这套产品 fork 的源码与运行时，不等于必须塞进某个固定目录。目录服从职责：调度归 Cron、平台执行归 Provider/MCP、事实归领域 owner、记忆归 Memory；如果现有目录制造职责冲突，就移动或重写，而不是为了目录整齐破坏架构。

## 最高优先级：Electron 只有显示和交互

Electron 只负责显示和交互，不参与其它任何东西。账号、Cookie、profile、浏览器、任务、
记忆、业务状态、自动化和执行全部属于 Hermes、MCP 或其它真实后端 owner。可见窗口不等于
业务所有权；任何实现难点都不能成为把后端责任塞进 Electron 的理由。

## 一句话定义

Marketing OS 是一个被彻底改造成“长期经营社交媒体账号”的 Hermes Agent。它不是营销页面、内容生成器、工具箱，也不是套在 Hermes 外面的业务壳。

用户给出目标，Agent 长期负责：理解人和账号、判断机会、获取证据、生产内容、受控执行、取得真实回执、复盘结果并让下一轮变得更准。

## 第一原则：经营，而不是生成

市面上的多数产品解决“生产一条内容”。Marketing OS 解决的是没有终点的经营过程：

```text
认识用户
→ 建模目标受众
→ 研究对标与平台
→ 形成账号定位
→ 发现机会并生产内容
→ 发布与取得回执
→ 回收指标
→ 复盘并形成学习候选
→ 下一轮更懂用户、账号和平台
```

因此，内容只是经营动作，不是产品终点。

## 第二原则：三核循环

产品最核心的不是某个模型或页面，而是三种时间方向的真相共同运转：

- `Memory`：过去真正学到了什么。
- `Preflight`：下一步是否值得做，以及为什么。
- `Receipt`：现实中到底发生了什么。

完整循环：

```text
Memory_t
  → Preflight_t
  → Action_t
  → Receipt_t
  → Retro_t
  → Candidate_t
  → Governance_t
  → Memory_{t+1}
```

预演会错，回执负责打脸；复盘只形成候选，候选经过用户确认、多样本支持或历史回放后，才能进入记忆、账号策略或技能。

## 第三原则：三类真相不能混

### 事实真相

发布 URL、post ID、素材 hash、模型/渲染凭证、播放、完播、收藏、关注、转化。它们来自平台或可验证执行结果，只记录，不解释。

### 预测真相

行动前对注意力、留存、信任、行动、账号适配、风险和成本的判断。必须先于行动固化，事后不可改写。

### 解释真相

“这个账号的框架型内容收藏高，但开头留存弱”一类结论。必须带 scope、证据、置信度和状态；一次结果不能升级成长期真理。

## 第四原则：内容是道，平台是术

内容运营研究人为什么停下、相信、共鸣、转发和行动。这些规律相对长期，是“道”。

平台运营研究分发机制、格式、合规、标签、节奏和用户习惯。这些规律随平台变化，是“术”。

同一内容内核到不同平台必须形成不同表达；垃圾内容不能因为迎合平台而成为长期策略，好内容也不能无视平台基因。

## 第五原则：影响力公式必须可解释、可校准

InfluenceOS 的初始表达：

```text
Influence
  = ReachPotential
  × HumanAttention
  × Retention
  × Persuasion
  × SocialPropagation
  × AccountFit
  × BusinessValue
  - RiskPenalty
```

第一版是可解释启发式，不是“预测流量的神秘 AI”。缺数据就降低置信度；有真实回执后按维度对账；只有重复模式通过回放，才产生权重候选。

## 第六原则：Hermes 是产品本体

Hermes 原生已有且更成熟的 Agent loop、session、task、checkpoint、memory、MCP、Skill、Plugin、Gateway、cron、工具审批和生态更新合同，直接使用或改写。

账号经营、受众、证据、内容、预演和复盘不是外部插件，而是 Hermes Agent 的原生经营能力。禁止为了少改上游而新增第二个 Agent、FastAPI sidecar、adapter 主链、第二数据库 owner 或第二记忆系统。

模块化仍然需要，但模块只代表职责边界，不代表外挂运行时。

## 第七原则：体验安静，底层强判断

用户不应该看到一排“预演门、权重、checkpoint、receipt、工具日志”。这些默认折叠在思考与执行里。

用户应该感受到：

- 它主动知道下一步，而不是等用户学会怎么问。
- 它知道哪些是事实、哪些是推断、哪些只是创意。
- 它会承认数据不足和预测错误。
- 它不会因为切页、隐藏或重启就停止任务。
- 它发布后会回来对账，不会做完即忘。
- 它越用越像懂这个用户和账号的运营总监。

UI 的作用是让智能可感知、可审阅、可控制，而不是展示系统内部复杂度。

## 第八原则：新用户前三十分钟必须获得价值

未登录、没有产业、不知道做什么的普通用户，也能通过自然对话完成初始建模：经历、资源、能力、兴趣、禁区、时间、商业目标和愿意服务的人群。

Agent 的第一句话不介绍功能，而是帮助用户得到第一个明确结果；首日应形成一个账号方向、目标受众假设和可以立刻验证的内容动作。

## 第九原则：安全和真实性高于自动化表演

- 未知不是 0。
- 没有 post ID/稳定 URL，不是发布成功。
- 没有真实素材来源，不宣称版权安全。
- 没有账号数据，不伪造粉丝画像。
- 付费、发布和敏感账号动作必须经过对应授权。
- 自动恢复不能重复外部副作用。
- API Key、Cookie、Token 永不进入记忆、回执 prose 或训练数据。

## 第十原则：两个数据飞轮，越用越强但不掠夺用户

Marketing OS 的长期护城河不是某个模型版本，而是两层相互校准的数据飞轮：

1. **用户私有飞轮**：用户偏好、拒绝记录、账号 DNA、受众、内容资产、预演、发布回执和指标只服务于该用户，默认留在其产品数据域。
2. **产品知识飞轮**：在用户明确同意后，只贡献去标识化、结构化、最小必要的特征与结果；大后端按平台、内容形态、受众和时间窗口聚合，形成版本化知识包和先验权重。

中央知识不能包含账号 ID、用户名、原文、私信、Cookie、Token、精确 URL 或可反推出个人身份的稀疏组合。未达到最小样本量的群组不得形成产品结论。全局知识只能作为预演先验，不能覆盖本地真实回执和用户明确偏好。

```text
本地事实/预测/回执
→ 本地复盘与个性化学习
→ 用户授权的匿名结构贡献
→ 后端多用户聚合与时间校准
→ 版本化知识包
→ 改善新用户冷启动和平台先验
→ 新的真实回执继续校准
```

模型厂商升级可以提升基础能力，但不能复制我们长期积累的经营证据、失败恢复经验、平台时效差异和经过现实回执校准的知识图谱。

## 第十一原则：短视频是视听传播，BGM 是一等变量

短视频采集不能只抓标题、话题和播放量。系统必须同时识别作品、声音、平台声音 ID、使用规模、传播速度、发布时间和互动指标。一个热门话题不等于一个热门声音，一条作品爆了也不等于它使用的声音具有可迁移性。

BGM 在部分短视频中的传播作用可以大于文案和画面，因此它必须完整穿过数据闭环：

```text
真实页面声音观察
→ 平台声音身份与跨作品复用
→ 速度/覆盖/新鲜度/内容适配/版权评分
→ 草稿 sound_plan 与发布前快照
→ 发布回执绑定 sound_id
→ 匹配内容或 A/B 变体复盘
→ 校准账号、平台和受众的声音偏好
```

单条作品只能证明“这个内容与这个声音一起获得了结果”，不能直接证明 BGM 的因果增益。只有同账号、相近内容、相近时间窗的匹配样本或受控变体，才能逐步提高声音归因权重。

## 第十二原则：记住用户，但不要相信用户能定义事实

系统需要理解用户的偏好、拒绝、目标和认知，但用户观点不能直接污染平台、赛道、账号或内容知识库。四类知识分别回答平台的“术”、赛道与市场的“环境”、账号的“现实”和内容的“道”：平台与赛道知识必须有来源与有效期；账号知识必须由真实回执和受治理复盘支持；内容知识必须是可观察、可反驳的人类注意力与传播先验。

Agent 可以说“你更偏好克制标题”，不能因为用户说过一句“每天发十条才有流量”，就把它当成抖音规则或账号增长结论。理解用户和服从错误事实是两回事。

## 第十三原则：先建经营世界模型，再做内容

账号定位不能从几个热门标签或大号榜单倒推。Hermes 必须依次建立创作者资产、多个赛道路线假设、行为受众、对标经营图谱、版本化定位和内容系统，再用可证伪实验进入三核循环。

赛道与市场知识是第四类公共知识；对标不是第五个知识库，而是当前账号与外部样本之间带证据、时间和角色的关系图。直接竞品、形式样本、信任样本、商业样本、跨界样本和反例承担不同作用。粉丝数和一个不透明综合分都不能替代多维判断。

## 第一版完成定义

第一版不是“页面都能点”，而是一个真实用户可以连续完成：

```text
自然目标
→ 用户/账号建模
→ 真实证据
→ 不可变预演
→ 可审稿内容资产
→ 用户授权
→ 真实发布回执
→ 指标回收
→ 预测与现实复盘
→ 待治理学习候选
→ 下一轮内容明显更准
```

任何没有进入这条纵向循环的功能，都不能优先于闭环收口。
