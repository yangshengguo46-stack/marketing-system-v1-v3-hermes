# Storyboard Creator

## When to Use
- After script is finalized, before production
- Planning shot-by-shot visual flow
- Communicating vision to a team
- Estimating production time and resources

## Storyboard Frame Template

```markdown
## Shot [Scene-Shot#]

**Visual**: [Describe what the viewer sees]
**Shot Type**: [EWS/WS/MS/MCU/CU/ECU/OTS/POV]
**Camera**: [Static/Pan/Tilt/Dolly/Track/Crane/Handheld]
**Angle**: [Eye-level/High/Low/Dutch]
**Lighting**: [High key/Low key/Rembrandt/Split/Natural]
**Composition**: [Rule of thirds/Center/Symmetrical/Leading lines]
**Action**: [What happens in this shot]
**Audio**: [Dialogue/VO/SFX/Music/Silence]
**Duration**: [X seconds]
**Transition to next**: [Cut/Dissolve/Wipe/Fade/Jump]

[Sketch or AI-generated reference image here]
```

## Scene Breakdown Process

### Step 1: Read the Script
- Identify scene boundaries
- Note emotional beats
- Mark key visual moments
- List all characters in each scene

### Step 2: Determine Shot Count
| Content Length | Shot Count | Avg Duration |
|----------------|------------|-------------|
| 60s short | 6-10 | 6-10s each |
| 3-5 min | 20-35 | 5-10s each |
| 10-15 min | 50-80 | 8-15s each |
| 30 min+ | 100+ | 10-20s each |

### Step 3: Assign Shot Types
- **Opening**: WS or EWS to establish
- **Dialogue**: MCU or OTS, alternating
- **Emotion**: CU on face
- **Action**: MS or WS with movement
- **Detail**: ECU on object/action
- **Closing**: WS or MCU to camera

### Step 4: Plan Transitions
- **Cut**: Standard, energetic — most transitions
- **Dissolve**: Time passage, memory — sparingly
- **Fade to black**: Scene/act end
- **Jump cut**: Time compression, energy
- **Match cut**: Visual continuity across scenes
- **Whip pan**: Fast transition, energy

## Storyboard for Short Video (60s)

```
SHOT 1 (0-3s)   MCU  Static   Eye-level    High key
  Visual: Host looking directly at camera
  Action: Hook line — "你知道吗？90%的人都做错了"
  Audio: VO + subtle BGM fade in
  Transition: Jump cut

SHOT 2 (3-8s)   CU   Dolly in Eye-level    High key
  Visual: Closer on host, slight zoom
  Action: Problem statement
  Audio: VO, BGM builds
  Transition: Cut

SHOT 3 (8-15s)  WS   Static   Eye-level    Natural
  Visual: B-roll of the problem in real life
  Action: Show the common mistake
  Audio: VO continues over B-roll
  Transition: Cut

SHOT 4 (15-25s) MCU  Static   Eye-level    High key
  Visual: Back to host
  Action: Introduce the solution
  Audio: VO, BGM shifts to hopeful
  Transition: Cut

SHOT 5 (25-35s) CU   Static   Slight high  High key
  Visual: Product/solution close-up
  Action: Demonstration
  Audio: VO + SFX (product sounds)
  Transition: Cut

SHOT 6 (35-45s) MS   Tracking Eye-level    High key
  Visual: Host using solution in context
  Action: Real-world application
  Audio: VO, BGM upbeat
  Transition: Cut

SHOT 7 (45-52s) MCU  Static   Eye-level    High key
  Visual: Host to camera
  Action: Result reveal / twist
  Audio: VO, BGM crescendo
  Transition: Cut

SHOT 8 (52-58s) CU   Static   Eye-level    High key
  Visual: Host direct to camera
  Action: CTA — "关注我，了解更多"
  Audio: VO, BGM resolves
  Transition: Fade

SHOT 9 (58-60s) MCU  Static   Eye-level    High key
  Visual: Logo / end card
  Audio: BGM outro
  Transition: End
```

## Visual Continuity Rules

### 180-Degree Rule
Keep camera on one side of an imaginary line between two characters. Crossing the line disorients the viewer.

### 30-Degree Rule
When cutting between shots of the same subject, change the angle by at least 30°. Otherwise it looks like a glitch.

### Eyeline Match
If a character looks off-screen, the next shot should show what they're looking at from their approximate perspective.

### Match on Action
Cut during movement — the action continues seamlessly across the cut. Most invisible transition.
